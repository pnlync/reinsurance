# M5 Reinsurance Engine & Excel Check

## 讲解

**业务问题**：给定任何一个再保方案，它在每个模拟年（和每个历史 as-if 年）里赔多少、会触发多少 reinstatement？

**输入**：M4 的 YELT（年–事件表）、YLT（年表），以及方案（QS 比例 q，外加 0–2 个 XoL 层 {A, L, c, n}）。

**输出**：每年 QS 赔付、每层每年赔付 R 和恢复比例 f。补费 RP = P × rate × f，要等 M6 定出 P 才算，所以引擎只存 f。

**关键公式**

- S'_e = (1 − q) S_e（QS 先扣，inuring）
- r_e = c · min(max(S'_e − A, 0), L)
- R_year = min(Σ r_e, (1 + n) c L)
- f_year = min(R_year / (cL), n)

**判断**

- 普通损失 A 不进 XoL，因为它不是一次事件。
- 年内按事件顺序消耗额度；模拟事件独立同分布，抽样顺序本身就是随机顺序。
- Excel 用 openpyxl 写**活公式**，再用 LibreOffice 无界面重算，逐格和 Python 比较。

**常见错误**

- 忘记 QS 先扣，XoL 直接用 S。
- n = 0 时仍然允许一年赔两次。
- 把 f 定义成"用掉的次数"而不是"恢复了多少额度"：它最多等于 n。

## 结果

- SPEC §11 golden test 全部通过：
  - toy 层逐年赔付 0, 0, 5, 0, 0, 50, 0, 30, 0, 0
  - f 为 0.1 / 1 / 0.6
  - burning cost 8.5
  - c = 0.8 时赔付 ×0.8，f 不变
  - q = 20% 时 XoL 赔付 50 和 12，burning cost 6.2
  - 年度上限三个案例
- Excel 核对：`toy` 和 `history` 两张表共 86 个单元格（逐年赔付、f、burning cost、碰到年数），经 LibreOffice 重算后与 Python 的最大相对差 4e-16（要求 < 0.01%）。history 表的两层：1-in-10 到 1-in-50（USD 2,480m 起赔、限额 7,520m），1-in-50 到 1-in-200（USD 10,000m 起赔、限额 16,640m）。

## Teach-back

1. 用手算走一遍 toy：第 8 年两场灾 55 和 90，50 xs 60，一次 reinstatement，赔多少？补多少费？
2. 如果 inuring 顺序反过来（先 XoL 再 QS）会怎样？
3. 为什么要 coinsurance（c < 100%）？

**参考答案**

1. 55 < 60 不赔；90 − 60 = 30 赔 30。年赔付 30，f = 30/50 = 0.6，补费 = 0.6 × P（100% 补费率）。
2. XoL 先作用于完整的 S，同一层会赔得更多；QS 再分走剩余损失的 q。QS 再保人的负担变小，XoL 再保人的负担变大，两份合同的价格都要变。合同必须写清 inuring 顺序。
3. 让分出人在层内保留利益、保持一致性（减少道德风险），也减少所需的市场容量、降低成本。FEMA 的层只分出 9–26%。
