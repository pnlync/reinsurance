# M11 Reporting

## 讲解

**业务问题**：把结论交给读者：管理层读备忘录，招聘方读 README，面试官看 CV。

**输出**：
- `README.md`：业务问题、三张 hero 图、推荐方案表、一段验证与基准、数据声明、`make all`
- `reports/memo.qmd → memo.pdf`：英文，5 页，六节
- `outputs/cv_numbers.json`：所有公开数字，附 git hash

**关键规则**：README 和备忘录由 `reports/templates/` 里的模板生成，**模板里的数字只能是 `{{占位符}}`**。
- 测试 `test_no_hand_typed_numbers_in_templates` 会列出模板里任何手写数字，只允许章节号、1-in-200 / 99.5% 的定义、2025 等少数常数。
- 与结果有关的句子（"1-in-200 在上限处"、"只有分出比例变化"、"下一步凸包的边际成本"）也按结果自动生成，结果变了文字会跟着变。

**判断**：
- 这台机器没有 LaTeX，备忘录用 Quarto 自带的 Typst 生成 PDF（D16）。
- "干净 clone 可复现"的做法：把 git 会提交的文件复制到空目录，加入冻结的原始数据（它们本来就不进 git），新建 uv 环境，跑 `make all`。结果 153 个数值与仓库完全一致（`outputs/tables/reproduction_check.json`）。

## 结果

- `make all` 从原始数据重建全部结果约 2 分钟；首次运行下载数据约 1 小时。
- 68 个测试全部通过（M0–M11）。
- CV 最终版写在 `private_notes/cv_bullets.md`（不公开）。

**参考答案**：
- 基准假设下，买 20% QS 加一层 1-in-5 到 1-in-200 的 Cat XoL（分出 80%），每年净成本约 USD 1.2bn，释放 82% 的 99.5% 经济资本（USD 20.7bn），相当于 5.9% 的资本成本，低于 10% 的股东资本成本。
- 这个结论成立的前提是再保人能分散风险（d = 0.5）；没有分散化就不该买。
- 尾部很大程度取决于 Harvey 和事件上限：删掉 Harvey，资本下降 57%。
- 预算不够时，Budget-first 方案每年 USD 370m 释放 26%。
